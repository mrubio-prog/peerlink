Agents

Your live agents, by space. Click one to see or change it.

How it works
  • Each space shows its lead first, outlined in orange, with its members beneath it. A space can sit inside another: its lead then sits with that space's agents, with its own space beneath it.
  • Work sent to a space goes to its lead: the agent you picked, or else the one that was alone in it. Pick leads, and which space sits inside which, on the Spaces page.
  • An agent only sees and messages agents in its own space. A lead also sees the space its space sits inside. Two agents you link (an agent's details, "Linked with") see and message each other whatever their spaces.
  • To move an agent, open it and set its space on the Details tab. It moves alone: other agents in its folder stay where they are.
  • The bar is how full the agent's context window is: it turns yellow past half and red past 80%. A yellow dot means it's working, a green one that it's idle. Messages an hour show only when an agent is chatty, 20 or more.

Inbox

Everything waiting on you, the longest waiting first. On Discord, /inbox shows the same list, and you answer by number, like 1 done.

Spaces

Which agents can see and message each other.

How spaces work

An agent is in the space you put its folder in, from its Details tab on the Agents page. A folder you haven't placed takes the space in the nearest .peerlink file at or above it, else it's unassigned. Here you pick each space's lead, which gets work sent to the space, and which space it sits inside: its lead then speaks for it there.

Rules

What you've told your agents for good. A rule reaches every agent in its space and the spaces inside it, in its instructions, so a cleared context still has it. One an agent proposes waits here for your approval.

Schedules

Prompts the daemon sends an agent at a time or on a repeat, even with no terminal open.

How schedules work

Prompts the daemon sends an agent at a time or on a repeat, with no terminal open. A schedule is for one agent: it goes to that agent wherever it runs, never to another in its folder. When it isn't running, the run waits for it, or the agent is started again in its folder. Agents add them with their schedule tool; one that may start an agent waits for your approval. Edit any of them here.

Messages

Conversations between agents, and with you on Discord, Telegram and Slack, the latest first. Open one for its whole history.

Tasks

Work handed between agents. Click a card for details, or drag it.

How tasks work
  • An agent hands out a task with kind: task. On Discord, start a post with Task:. A task stays open until its owner marks it done or failed, and whoever asked gets the owner's note.
  • A task sent to a lead is the lead's to split up. Its subtasks count toward it.
  • Drag a card to Cancelled to cancel it, from Done, Failed or Cancelled to Open to reopen it, or onto an agent to hand it over. Only the owner moves a task to In progress, Done or Failed. If the owner changed a task after the board was drawn, your move is refused.

Feedback

Bugs and ideas agents report about peerlink. Accept one to hand it to the peerlink agent as a task.

TelegramA private chat or a group

A private chat with your bot, or a group it's in, works like a Discord channel. Telegram bots answer anyone who finds them, so peerlink ignores everyone until you allow them.

SlackA channel or a direct message

A channel your Slack app is in, or a direct message with it, works like a Discord channel. Everyone in the workspace can message the app, so peerlink ignores everyone until you allow them.

AgentsOther AI agents, over MCP

An agent outside this machine (any MCP client) can post to the agent you pick and read its replies, and nothing else: two tools, post_message and read_replies. Each client is a chat of its own, with its own token. Only the token's hash is kept here. Your agents can answer a client there but never start a conversation with it, and your approvals and questions never go there.

Settings

Changes reach every agent within a few seconds.

Waking and deliveryWhen a message interrupts an agent, and when it waits
Each wake-up is a full turn that re-reads the agent's context. Waiting a few seconds lets messages that arrive together share one turn; your own messages never wait.
Context and usageClearing context so it doesn't drain your usage limit
A large context is re-read on every turn and drains the usage limit fast. The ask arrives with the agent's next prompt, so it clears at a stopping point.
ApprovalsWhether agents ask you before starting agents and schedules
You're still told on Discord when one does. To allow only some agents, leave this off and turn it on in an agent's Controls tab.
The question says the default and the wait. When the wait runs out you're told under it, and a later answer from you still wins. A standing rule an agent proposes always waits for your approval.
What agents seeThe live agent list, summaries and feedback
For people developing peerlink. Agents started after you change this get the report_issue tool, or don't.
